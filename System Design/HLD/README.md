# Overview
- Understanding Requirements in detailed way is necessary.
- Key Aspects:
  - Requirement Analysis. - asking right set of questions is imp which to focus on - either it's high level design or UI related component design.
    - Functional Requirement - think from product manager POV.
    - Non-functional Requirement - think from architect POV. 
  - System Architecture - diff services and how they are going to interact etc.
  - Module / Component - relationship between them
  - Data design / Interfaces / API design -
  - Tech Choices - any libraries, state management

  Key Takeaways:
  - problem statements are not specific - it's open ended.
  - asking right set of questions is key
  - donot make assumptions
  - Drive the interview with interviewer's intent.
  - HLD isn't about Coding
